窗口内 / Agent 成本

Spotify Portal：用两层路由把大文件读取交给便宜模型

发生了什么：Spotify 工程文章给出一个 Claude Code 插件案例，作者报告将自身 token 使用量削减约 90%。

技术核心：Portal 的声明式 AiKA Modes 在临时运行时执行；shunt 插件先用 PreToolUse hook 拦截超过阈值的大文件读取，再由脚本把文件和问题交给低成本 worker，生成样板代码时也只把最终文件写回工作区。

为什么重要：上下文路由不只节省推理费，也能阻止无关文本污染主 Agent 的上下文窗口。

成熟度/风险：90% 是单个作者的工作流结果，不是通用基准；路由错误会丢失上下文，跨模型传输还需评估数据边界、审计与失败回退。

证据：Spotify Engineering

窗口内 / 多模型编排

HydraFusion：运行时在单模型、级联与批评流程间选择

发生了什么：GitHub 发布 Copilot CLI 研究预览，让用户像选择模型一样选择 HydraFusion。

技术核心：路由器依据推理、编码、调试和工具能力信号选择 Single、Cascade 或 Critique；批评模型在隔离且无工具的上下文中审阅，系统对每一段设置超时、取消、成本记账和补丁验证。

为什么重要：优化单位从“选哪个模型”上移为“如何组合模型”，并把成本与仓库状态一致性纳入运行时。

成熟度/风险：仍是研究预览，主要面向首轮、单提示任务；67% 成本下降与质量差异来自指定模型、定价假设及三套离线基准，不能直接外推到生产。

证据：GitHub 官方博客

窗口内 / AWS Serverless

AWS MCP Server 聚合 Lambda 跨资源诊断

发生了什么：AWS 为其 MCP Server 增加 serverless capability，面向 Lambda 及相连服务的故障诊断。

技术核心：一次调用可检查 API Gateway、EventBridge、S3、DynamoDB、SNS、SQS 与 Step Functions，关联七日基线、重复错误、部署配置、变更时间线和跨服务延迟。

为什么重要：将多次 API 编排压缩为有上下文的诊断结果，可降低 Agent token 消耗并缩短排障路径。

成熟度/风险：能力免费但属于托管访问面；应以最小权限限制可见资源并审计调用。MCP Server 本体运行在弗吉尼亚北部和法兰克福，需核对数据驻留要求。

证据：AWS 官方公告

窗口内 / AWS 容器部署

ECS 用健康比例提前完成滚动部署

发生了什么：Amazon ECS 推出滚动部署 Early Success Criteria，可按健康任务比例而非全部任务到齐判定成功。

技术核心：例如期望 100 个任务、阈值 90% 时，90 个健康任务即可解锁流水线，余下实例转为常规扩容；旧 revision 清理由 BLOCKING 或 DEFERRED 控制。

为什么重要：GPU 等稀缺容量和长连接工作负载不再必须让最慢的一批任务阻塞整个交付链。

成熟度/风险：“部署成功”不再等于达到全部期望容量；告警、SLO 和后续发布门禁必须继续观察剩余扩容及异步清理。

证据：AWS 官方公告

15h.org：为 AMD Family 15h 延续可审计固件支持

成熟度/风险：硬件发布于 2011 至 2014 年，性能功耗、备件和安全更新均有现实限制；站点也把部分主板明确标为初步支持，部署前必须逐板核对状态。
