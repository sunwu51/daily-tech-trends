Go HTTP/1：关闭响应体后，自动尝试回收连接

事件简介：Go 官方介绍从 1.27 起的 HTTP/1 连接复用调整。过去只读取状态码、随后关闭响应体的程序，会因未读完正文而丢弃连接；即使 JSON 已解析成功，末尾未消费的换行也可能触发同样问题。本文是行为解释，并非当天发布新版本。

技术机制：net/http.Transport 在后台排空剩余正文，最多处理 256 KB 或等待 50 毫秒，成功后把连接放回空闲池。遇到 Connection: close 则跳过无益读取；HTTP/2 用独立数据流复用连接，不需要这套排空办法。

实际影响：编辑判断：频繁调用健康检查或只关心状态码的 API 客户端，可减少重复 TCP/TLS 握手，也少维护一套带超时、字节上限和并发清理的自制逻辑。应用仍应及时关闭不再需要的响应体。

限制与来源：大正文或慢速传输超过上限后仍可能无法复用。文章约五倍的速度差来自作者机器上的特定 HTTP/1 测试，不能推广为所有请求的加速比例；后台策略以后也可能调整。

Hyperdrive MySQL：共享缓存必须保存同一种协议表示

事件简介：Cloudflare 宣布 Hyperdrive 的 MySQL 支持已正式可用，并披露 beta 期间空结果和请求挂起问题的修复。Hyperdrive 为 Workers 维持数据库连接池，还可缓存查询结果，省去每次请求重建远程 SQL 连接。

技术机制：靠近 Worker 的 Client 与靠近数据库的 Endpoint 若位于同一数据中心，会共享缓存。MySQL 连接会协商能力标志；mysql2 对结果结束标记的支持与 Hyperdrive 不同，Client 转换后的字节曾混入 Endpoint 期待的格式。修复让两端始终缓存按 Hyperdrive 能力编码的标准表示，再在返回时转换。

实际影响：编辑判断：维护数据库代理的团队应同时测试缓存命中、节点共址和客户端能力差异。查询文字相同不代表序列化结果可互换；固定缓存表示可避免错误把结束标记识别为数据边界。

限制与来源：故障需要共享缓存及能力不匹配等条件，不能泛化为所有 MySQL 查询失效。修复后 99.99% 连接成功率是厂商生产统计；文章没有提供独立可复现的全负载基准。

GitHub 星标历史：在聚合前用时间范围缩小扫描

事件简介：GitHub 介绍新的仓库星标历史接口：一次返回最多 30 周的每日计数，不附用户身份。旧工具为画增长曲线，需要分页读取当前星标用户及时间；访问限制后，这一用途改由聚合接口承接。

nvm：按项目选择 Node.js，按 shell 隔离运行版本

简介：nvm-sh/nvm 是供 JavaScript 开发者在命令行安装和切换 Node.js 的版本管理器，按用户安装、按 shell 生效，适用于 Unix、macOS 及 Windows WSL 等环境。它解决多个项目依赖不同 Node 版本时反复替换系统安装的问题。

技术特点：nvm use 通过当前 shell 的路径选择已安装版本；项目根目录的 .nvmrc 保存版本要求，无显式参数时工具向上查找该文件。nvm install 按要求补装版本，nvm exec 可在指定版本下执行命令，各版本有自己的全局包目录。

适用场景与价值：编辑判断：开发者同时维护旧服务与新前端时，可进入项目后按 .nvmrc 切换，再运行测试，避免全局升级 Node 后破坏另一套环境。把版本要求放进仓库，也让新成员知道该安装哪版，而不是逐人询问。

限制与来源：nvm 是 shell 函数，非交互式 CI 必须显式加载；不原生支持 Fish，Windows 原生环境不能与 nvm-windows 混为一谈。npmrc 的 prefix 设置不兼容；缺少平台二进制时可能退回耗时的源码编译。
