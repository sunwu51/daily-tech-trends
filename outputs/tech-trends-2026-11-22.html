02 · Java4Shell 镜像修复：同时核对 JVM、处理器与实际启动选项

事件简介：Docker 说明其强化镜像中各 Java 发行版的修复进展。Java4Shell 位于 OpenJDK 运行时的 Base64 解码器；即使业务由其他语言编写，随产品打包的 JVM（Java 虚拟机）也需要检查。本项聚焦 Java，不重复本周 nginx 漏洞。

技术机制：支持 AVX-512 VBMI 的 x86-64 处理器会使用特定汇编优化路径。异常填充使尾部输出长度计算错误，造成越界写入；应用之后拒绝输入，也不能撤销此前的内存破坏。

实际影响：编辑判断：集群应逐镜像读取 java -version，并核对调度节点。拉取修复基础镜像后，还要重建业务层并重新部署；等待修复时可按文档关闭 UseBASE64Intrinsics，并确认选项传到每个 JVM。

限制与来源：并非所有硬件可触发，也不存在所有应用通用的利用链。文章所列 Temurin 部分版本仍在等待，不能把近期重建标签当已修复证明；供应商状态以所读公告为准，本期未复现攻击。

06 · Grafana SQL 表达式：在服务端合并不同数据源的查询结果

事件简介：Grafana SQL expressions 在数据源已返回结果后、发送给浏览器展示前，用类似 MySQL 的语法处理数据。它服务于需要关联多个查询的看板作者，不要求原数据都存入同一个数据库。

技术机制：面板内先建立 A、B 等基础查询，用它们的 RefID 标识作为 SQL 表名，再进行连接、过滤和聚合。时序结果会转成含时间及数值字段的表，作者应先检查列结构，再验证输出是否符合所选图形。

实际影响：编辑判断：将服务流量与另一来源的业务属性对应时，可在展示层连接结果，减少只为看板另建一条数据搬运任务；这种做法仍要求先在来源查询里缩小数据范围。

限制与来源：只能使用后端数据源；每面板或告警仅一条 SQL 表达式，不能串接表达式结果。默认输入上限十万单元格、超时十秒；无数据或列变化可能使结构推断失败，不能当通用跨库查询引擎。
