Agent 安全 / 实践讨论

无沙箱 MCP 服务器实际上拥有用户的全部权限

发生了什么：作者检查自己运行的 shell MCP 服务器后发现它以同一 UID 工作，因此可以读写用户文件、访问 SSH/AWS 凭据、运行本地二进制并向外发起网络请求。

技术核心：风险来自 POSIX 权限继承，而非特殊漏洞；当文件中的提示注入诱导 Agent 调用工具时，服务器能执行的动作就是用户能执行的动作。文章提出以只读 rootfs、--cap-drop=ALL、默认断网和显式 bind mount 组成默认拒绝的容器边界。

为什么重要：它把“我信任这个 MCP”转换成可检查的进程、UID、网络和文件系统边界，直接影响编码 Agent 与本地工具的部署方式。
成熟度/风险：这是单篇实践文章和作者工具 mcp-box 的设计主张，不是独立审计；容器仍需按宿主内核、挂载和凭据暴露面复核。

来源：原文 · mcp-box · HN 讨论

技术核心：项目提供本地、Docker、SSH、Singularity、Modal、Daytona、Vercel Sandbox 等终端后端，另有定时任务、语音转写、并行子 Agent 和可插拔模型提供商。它把会话持久化与执行环境选择放在同一控制面。

快照证据：237,576 Stars / 48,196 Forks；本轮 +405 / +177。

成熟度/风险：这是既有项目的实测增长，不是新发布。README 的“可运行在 $5 VPS”等描述未替代容量和安全评估；本地后端仍继承宿主权限，MCP、技能和代码执行应配合 OS 级隔离。
