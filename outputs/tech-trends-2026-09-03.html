Kubernetes / 弹性伸缩

Kubernetes v1.37 将 HPA 缩容至零推进到 Beta

发生了什么：v1.37 为 HorizontalPodAutoscaler 增加把工作负载缩到 0 个副本的 API 支持；功能为 Beta 且默认启用。

技术核心：使用合适的对象指标或外部指标时，HPA 可在队列消费者、批处理等无工作时移除最后一个 Pod，并在指标变化时重新拉起。

为什么重要：对预留 CPU、GPU 的间歇性负载，这把 scale-to-zero 从附加组件或 Alpha 开关变成核心能力，直接影响空闲成本模型。

成熟度/风险：仍是 Beta；唤醒延迟、指标可靠性和零副本时的事件积压须在真实流量下验证。

证据：Kubernetes 官方发布

RAG / 合规云

Bedrock Web Search 进入 AWS GovCloud (US-West)

发生了什么：AWS 将 Bedrock 的内置服务端 Web Search 工具带到 GovCloud (US-West)。

技术核心：该工具为受支持的 OpenAI GPT 模型提供网页 grounding，并在响应中给出所用来源的引用；检索与基础设施由 Bedrock 托管。

为什么重要：对时效信息问答，合规敏感工作负载可获得可追溯的外部证据，而无需自行运营爬虫或搜索索引。

成熟度/风险：区域、模型支持和网页来源质量均有边界；引用不能替代对高风险结论的人工核验。

证据：AWS 官方公告

MCP / 工具治理

Amazon Quick 为连接器增加 MCP 同步与逐工具控制

发生了什么：Amazon Quick 新增连接器工具设置、MCP 同步和权限选项，覆盖 Outlook、Slack、Salesforce、Jira 及自建 MCP 服务等接入。

技术核心：管理员或连接器所有者可以单独启停工具，并决定工具是否必须征得用户同意；MCP 服务器的工具定义可同步更新。

为什么重要：Agent 工具接入从“一次性全开”转向最小授权和变更同步，降低企业把 SaaS 与内部服务接给模型时的治理摩擦。

成熟度/风险：同步会改变可调用面；仍应审计 OAuth 范围、审批默认值和 MCP 服务端的版本变更。

证据：AWS 官方公告

客户体验 / Agent 编排

Amazon Connect 的 Agentic CX Designer 正式可用

发生了什么：AWS 宣布面向语音和数字自助服务的 Agentic CX Designer 正式发布，提供无代码设计画布。

技术核心：画布把确定性流程逻辑与大语言模型能力组合，覆盖对话设计、业务系统集成、测试和发布。

为什么重要：它把客服 Agent 的编排门槛下移给业务团队，同时保留流程图式的可见控制面，缩短从设计到上线的路径。

成熟度/风险：GA 不代表业务正确性；需针对转人工、提示注入、错误补偿和高影响决策建立测试与监控。

证据：AWS 官方公告

Serverless / 性能

Lambda SnapStart 支持容器镜像函数

发生了什么：AWS 宣布 SnapStart 可用于以容器镜像打包的 Lambda 函数，目标将数秒级启动降至低于一秒。

技术核心：这是按需启用的能力，适用于依赖较大、镜像可达 10 GB 的容器化函数，以减少下载镜像层和运行时/应用初始化的启动成本。

为什么重要：采用容器交付标准的团队不必在部署一致性与低延迟之间二选一，尤其适合突发流量 API 与事件处理。

成熟度/风险：实际收益取决于初始化路径；须测试快照恢复时的连接、随机数、凭据和区域/运行时兼容性。

证据：AWS 官方公告

MLOps / CI/CD

SageMaker Unified Studio CI/CD 加入笔记本晋级与 AI 清单生成

发生了什么：SageMaker Unified Studio CI/CD 的开源部署工具包新增跨环境 notebook promotion，以及生成部署 manifest 的 Agent skill。

技术核心：生成器检查项目连接、存储和工作流，输出部署清单，并采用最小权限 IAM、环境变量替代硬编码资源标识和安全默认值。

为什么重要：数据团队可以把探索性 notebook 更一致地推向多环境部署，并减少手写配置的重复劳动与漂移。

成熟度/风险：AI 生成的 IAM 和清单必须经过代码审查；自动“安全默认值”不能替代组织自己的隔离与审批策略。

证据：AWS 官方公告

云治理 / 可观测性

AWS Config 新增 60 类资源覆盖

发生了什么：AWS Config 新支持 60 种资源类型，涵盖 Bedrock、EC2、SageMaker 与 Organizations 等服务。

技术核心：启用“记录所有资源类型”的账户会自动跟踪新增类型；这些资源也能进入 Config rules 与 aggregators。

为什么重要：AI 与基础设施资产扩张后，资产发现、审计和修复的盲区会迅速成为合规风险；这次扩展提高了统一治理面覆盖。

成熟度/风险：记录不等于合规；需确认区域覆盖、规则语义、交付延迟和新增记录带来的成本。

证据：AWS 官方公告

混合云 / 政府云

第二代 AWS Outposts 机架支持 GovCloud 区域

发生了什么：第二代 Outposts racks 现可连接 AWS GovCloud (US-East) 与 (US-West)。

技术核心：Outposts 把 AWS 的基础设施、服务、API 和工具延伸到本地数据中心或托管机房，同时回连区域进行应用管理。

为什么重要：需要低延迟访问本地系统或数据驻留的政府与受监管负载，获得更一致的混合云运行方式。

成熟度/风险：可用服务集合、容量、网络依赖与故障域不同于纯区域部署；应按具体工作负载验证。

证据：AWS 官方公告

数据库 / 性能调优

RDS for SQL Server 可配置额外 18 个 trace flag

发生了什么：Amazon RDS for SQL Server 通过数据库参数组支持额外 18 个 SQL Server trace flag。

技术核心：这些开关可改变基数估计、锁升级、统计信息和内存处理等引擎行为，用于面向具体工作负载的诊断和性能稳定化。

为什么重要：托管数据库用户获得更细的兼容性与优化控制，而不必放弃 RDS 的托管运维模式。

成熟度/风险：trace flag 可能修复也可能放大特定查询问题；应在回放或预生产环境基准测试并记录回退方案。

证据：AWS 官方公告

联络中心 / 多语言 AI

Amazon Connect 将自动绩效评估扩展到马来语

发生了什么：Amazon Connect Customer 现可用生成式 AI 自动评估马来语的人类与 AI 坐席，并支持以英语评估非英语对话。

技术核心：管理者以自然语言定义评分准则，系统输出带理由的评估；功能覆盖 8 个 AWS 区域。

为什么重要：多语言联络中心能在统一质量框架下扩大自动质检覆盖，减少语言成为运营度量孤岛的情况。

成熟度/风险：跨语言评价可能引入语义、口音和文化偏差；高影响的人事决策应保留抽检、申诉与人工复核。

证据：AWS 官方公告
