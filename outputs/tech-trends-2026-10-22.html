03 · Cloudflare WAF：结合请求和响应识别利用迹象

事件简介：Cloudflare 为 Web 应用防火墙新增全事务检测与响应规则，覆盖免费计划。传统请求检查识别可疑输入，新能力把它与源站实际返回的结果关联，帮助区分一次被拒绝的尝试和可能泄露信息的响应。

技术机制：检测先附加元数据，规则再决定记录或阻断。例如路径穿越请求若同时返回配置文件特征，托管检测可据此标记；响应规则在正文送到请求者前，以阻断页替换源站响应。自定义规则可组合路径、请求头、响应状态和响应头。

实际影响：编辑判断：文件下载服务可将输入异常与输出证据一起核查，减少仅凭正常文档中出现配置样例就作结论的情况；安全人员还能按具体规则 ID 回查事件，确认哪条策略采取了动作。

限制与来源：响应阻断不能撤销源站已经执行的动作。每个客户最多三条自定义响应规则，目前不能自行用响应正文写规则；付费检测字段仍在逐账户推出。应区分托管正文检测与尚不可用的自定义正文条件。

04 · GitHub 缩小写入串行范围：不同分支不必共等仓库锁

事件简介：GitHub 披露向 Azure 迁移 Git 存储的过渡设计，称 99.99999% 仓库已在两处保存副本。最繁忙仓库受约 25 毫秒跨区域往返限制；问题在于旧写入过程持有整个仓库的锁，慢副本会让后续写入一同等待。

技术机制：新设计按 reference，即分支或标签引用，分别串行化：争用同一引用的写入仍排序，不同引用可同时在途。另一条路径让“虚拟写副本”将数据持久化到 Azure Blob Storage，再由不加入写入仲裁的临时读副本加载缓存。

实际影响：编辑判断：多个开发者和代理各推自己的分支时，缩小排序范围可减少相互排队；把读计算与持久存储拆开，则让读流量扩容不必增加完整写副本。内部现实流量测试的三至四倍吞吐是厂商数据。

限制与来源：文章描述正在推进的架构，不能理解为所有仓库已完成终态迁移。虚拟读副本初期在后台对齐状态，只适合部分读工作负载；覆盖全部读取还需将状态核对移入请求路径，写入仲裁也仍是后续瓶颈。
