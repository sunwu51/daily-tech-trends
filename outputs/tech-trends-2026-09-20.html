当前 GitHub Trending · 计算机使用 Agent

Cua：给 Agent 配置隔离桌面、跨平台驱动与评测轨迹

简介：Cua 面向构建“计算机使用”Agent 的开发者，把可操作的 Linux 云桌面、Apple Silicon 上的本地 macOS/Linux 虚拟机、跨 macOS/Windows/Linux 的桌面驱动和任务评测工具放在一个开源项目中。用户可带自己的 Agent 与模型，让它执行命令、截图并操作原生应用或浏览器。

技术特点：Sandbox SDK 统一本地沙箱与云端 Fleet 的生命周期；Cua Driver 可经 CLI、MCP 或类型化 SDK 暴露界面检查和操作，平台允许时可后台执行而不抢鼠标焦点。Cua Bench 把任务、参考解法、验证器和轨迹导出连起来，CUA-S1 则试验用结构化界面元素做表单等边界明确的快速决策。

适用场景与价值：做桌面回归或 Agent 评测的团队可先领取隔离桌面，运行同一任务并保存截图、奖励与操作轨迹，避免直接把实验 Agent 放进员工主机；这是依据隔离与评测能力作出的编辑判断。

限制与来源：云 Fleet 的池在任务结束后仍可能保留付费容量，必须按文档清理；本地 Lume 依赖 Apple Silicon，Driver 的后台能力有平台边界。CUA-S1 仍是源码优先的早期研究发布，模型和数据另有许可。来源：README：组件、运行路径与限制

当前 GitHub Trending · 云开发环境

Coder：让开发者与编码 Agent 共用自托管工作区控制面

简介：Coder 是自托管的云开发环境平台，面向要在自有基础设施上集中交付 IDE、依赖和编码 Agent 的团队。管理员用 Terraform 定义 EC2、Kubernetes Pod 或 Docker 工作区，开发者仍可从 VS Code、JetBrains 等现有编辑器接入。

技术特点：工作区经 WireGuard 安全隧道连接，并可在空闲时自动关停。Coder Agents 的循环运行在组织控制面，模型凭据不进入工作区；每次动作带用户身份，同时由 AI Gateway 集中处理模型认证、成本记录和审计，因此隔离的执行环境与模型治理可以分开管理。

适用场景与价值：平台团队可为新成员或外部 Agent 从同一模板启动短期开发 Pod，预装代码与工具，任务完成后自动停机；相比在个人电脑复制环境，这能把资源期限、身份和模型支出留在同一审计链中。

限制与来源：快速体验使用内置数据库与临时访问域名；生产部署要求 PostgreSQL 13+、外部访问 URL，并需按验证架构自行定容。专属支持和部分大团队能力属于付费版。来源：README：架构、Quickstart 与集成

当前 GitHub Trending · 私有检索

Hister：为浏览记录与本地文件建立自己的全文索引

简介：Hister 是可本地或自托管的个人搜索引擎，面向需要重新找到自己看过网页和保存文件的用户。浏览器扩展自动提交所选页面正文，也可导入历史、书签、目录和单个文件；结果可从 Web、终端界面、命令行或连接 MCP 的 AI 助手查询。

技术特点：它索引正文而不只存标题和 URL，并支持字段过滤、短语、通配符、否定和结果优先级。默认无遥测、无强制云同步，文档与索引保存在用户指定的 Hister 服务器；多用户部署会隔离各自文档。语义检索是可选层，需要用户另配 embedding（向量嵌入）端点。

适用场景与价值：研究者可让扩展持续收集自己访问过的技术页面，之后让 Agent 经 MCP 找回原文片段，而不用把全部浏览资料交给公共搜索服务。全文和精确查询也为向量召回失败时保留可解释的检索路径。

限制与来源：服务必须持续运行才能索引与搜索；启用远程 embedding 会把文档文本发给所选端点，需另行审查隐私。源码构建要求 Go 1.26、npm 和支持 CGO 的 C 编译器，许可为 AGPLv3+。来源：README：功能、隐私与开发要求

当前 GitHub Trending · 文档理解

Docling：把 PDF、办公文档、音视频转成统一结构

简介：Docling 是面向检索增强生成、Agent 和文档分析流水线的本地文档转换工具。它读取 PDF、DOCX、PPTX、XLSX、HTML、图片、邮件、音频及多种专业格式，输出 Markdown、HTML、WebVTT、DocTags 或无损 JSON，也可作为 CLI、Python 库、API 服务或 MCP 服务使用。

技术特点：解析流程把版面、阅读顺序、表格结构、代码、公式、图像类别和 OCR 结果汇入统一的 DoclingDocument；视频输入则组合自动语音识别转录与代表性关键帧。统一中间表示让同一份复杂 PDF 能分别导出给人阅读的 Markdown 和保留结构的 JSON。

适用场景与价值：企业建立内部知识库时，可在隔离环境把扫描合同、演示文稿和会议录音先转换为统一对象，再交给 LangChain、LlamaIndex 或自建索引，减少为每种文件各写解析器的工作。

限制与来源：Python 3.9 已在 2.70.0 后停止支持，需 3.10+；代码为 MIT，但选用的 OCR、视觉语言和语音模型各有独立许可。元数据抽取与复杂化学结构理解仍列为“即将支持”，不能当成现有能力。来源：README：格式、结构、运行方式与路线图

当前 GitHub Trending · QUIC / HTTP/3

quiche：把 QUIC 连接状态交给库，把 I/O 与事件循环留给应用

简介：Cloudflare/quiche 是 Rust 实现的 IETF QUIC 传输协议与 HTTP/3 库，服务需要把新传输协议嵌入代理、DNS 或客户端的系统开发者。它已用于 Cloudflare 边缘 HTTP/3、Android 的 DNS over HTTP/3，也可作为 curl 的 HTTP/3 后端。

技术特点：quiche 提供处理数据包与维护连接状态的低层 API，应用自行提供 UDP socket、事件循环和定时器：收到包调用 recv()，用 send() 生成出站包，超时后调用 on_timeout()。SendInfo.at 给出 pacing（平滑发包）时刻；薄 C API 允许 C/C++ 通过 FFI 链接同一静态库。

适用场景与价值：已有自定义网络运行时的代理团队可保留自己的 I/O 调度，只把握手、流和拥塞状态交给 quiche；这种边界避免库强迫应用更换整个事件循环，但也要求集成者正确驱动定时器与发包节奏。

限制与来源：许多流量与并发上限默认为零，应用必须按场景配置；示例客户端/服务器不适合生产，附带证书为自签名。构建需 Rust 1.88+、CMake 和 BoringSSL，Windows 还需 NASM。来源：README：API、pacing、FFI 与构建要求
