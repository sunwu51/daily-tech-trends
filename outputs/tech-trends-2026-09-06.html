当前 Trending / 图表生成

Diagram Design：面向 Agent 的编辑式图表技能

简介：这是给 Claude Code、Codex 等 Agent 使用的图表技能，面向需要架构图、流程图和数据图的产品与工程团队。仓库提供 39 种图形类型及静态 HTML/SVG 输出。

技术特点：布局语法与语义模式分离，同一套节点语义可套用架构、Sankey、UML 等布局；默认无构建步骤、无 JavaScript 和外部图片依赖，也能重绘 draw.io 或 Mermaid 源文件。

适用场景与价值：文档代理可直接生成可审阅的静态图，团队无需为每张图进入 Figma 再手工统一格式；静态文件便于放进代码仓库和评审流程。

限制与来源：质量依赖 Agent 对输入结构的理解，动效是可选项且默认关闭；39 种类型仍有固定表达边界。

证据：官方 README

当前 Trending / 编码代理

OpenCode：开源终端编码代理

简介：OpenCode 是可自托管的开源 AI 编码代理，支持 macOS、Windows、Linux 以及桌面 Beta 客户端，服务需要在终端探索和修改代码的开发者。

技术特点：内置 build 与只读 plan 两个 Agent，并提供 general 子代理；可通过 npm、Homebrew、Scoop、Nix 等渠道安装，模型和供应商保持可替换。

适用场景与价值：先用 plan Agent 浏览陌生仓库，再切换 build 执行改动，能把分析与写入权限分开；跨平台安装降低团队统一工具链的摩擦。

限制与来源：桌面端仍标为 Beta，完整行为取决于所接模型和本地权限；生产使用需自行配置凭据和审计。

证据：官方 README

窗口内 / 多模型编排

HydraFusion：按任务阶段路由多个模型

事件简介：GitHub 在 9 月 4 日介绍 HydraFusion 研究预览，用选择性编码工作流在离线评估中比较多模型协作与单模型基线。

技术机制：路由器依据任务阶段和反馈，把更昂贵的模型留给需要的步骤，而不是整条链路固定使用同一模型。

实践影响：团队可先把自己的任务集离线重放，分别测质量、延迟和费用，再决定哪些环节值得升级模型。

限制与来源：评估属于受控研究预览，基线和生产收益尚未独立复现。

证据：GitHub Blog

窗口内 / 节点安全

Kubernetes 1.37：Rootless Kubelet 晋级 Beta

事件简介：1.37 将 KubeletInUserNamespace 推进到 Beta，使 kubelet、CRI/OCI runtime、CNI 与 kube-proxy 可在 Linux user namespace 以非 root 运行。

技术机制：功能门控把节点组件放入 user namespace，减少组件直接持有主机 root 权限的范围。

适用场景与价值：多租户平台可在测试节点先启用并观察逃逸后的影响面，随后按插件兼容性逐步推广。

限制与来源：Beta 不保证所有存储、网络插件和运行时兼容，性能与故障数据仍待生产验证。

证据：Kubernetes Blog

近期发布 / AI 评测

Docker Sandboxes：把评测执行记录成工件

事件简介：Docker 文章展示用 Sandboxes 隔离 AI 评测环境，使同一任务可在固定依赖下重跑。

技术机制：YAML 定义评测，executor 决定在本机或 SBX 执行；工件记录命令、标准输出、错误、退出码、耗时及配置摘要。

适用场景与价值：模型或提示升级前，团队可以重放任务集并对比运行证据，而不是只保存一个不可复核的分数。

限制与来源：沙箱不自动解决脱敏、网络差异或 GPU 非确定性，仍需定义环境边界。

证据：Docker Blog

当前 Trending / 早期 Agent 基础设施

Ruflo：面向 Claude Code 与 Codex 的元编排层

简介：Ruflo 是包在编码代理外部的执行层，目标用户是要协调多代理、记忆和远程通信的团队。README 描述可用 CLI/MCP 初始化，并支持本地、联邦和企业安全场景。

技术特点：架构由路由器、代理群组、记忆和学习循环组成，提供 100 多个专用 Agent、并行 swarm、跨机器 federation 与沙箱控制。

适用场景与价值：长任务可把重复步骤和成功模式写入记忆，再由路由器分派给不同代理，减少每次从零配置；但这仍是工程推断。

限制与来源：功能面很大，README 的下载和性能数字需独立复测；跨机器通信会扩大凭据和数据隔离责任。后续应看真实任务成功率与故障恢复证据。

证据：官方 README

当前 Trending（中文）/ 早期量化工具

Sequoia-X：A 股本地量化选股系统 V2

简介：Sequoia-X 面向 A 股收盘后选股，使用 Python、baostock 和本地 SQLite，日常模式会增量更新数据并把结果推送到飞书。

技术特点：OOP 结构把数据、策略和通知分层；内置海龟突破、均线放量、RPS 等策略，支持 8 进程增量抓取与一次性历史回填。

适用场景与价值：个人研究者可在本地保留后复权日 K 数据，定时运行策略并收到候选列表，避免手工下载和反爬站点依赖。

限制与来源：数据来自免费 baostock，策略结果不是投资建议；回测、实盘滑点和接口稳定性尚未由独立证据确认。后续应关注测试覆盖和长期数据质量。

证据：官方 README
