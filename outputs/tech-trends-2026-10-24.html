01 · Origin Range Requests：按缓存块补齐大文件的缺失字节

事件简介：Cloudflare 将重写后的大文件部分读取缓存开放给全部计划，用户用 Cache Rule 开启即可。HTTP Range 请求只索取文件的一段字节，常用于视频跳转、断点下载和模型文件读取；旧实现的固定分段配置可能为一次小读取回源大量数据。

技术机制：新实现沿用 Pingora 的磁盘缓存块，先读已有字节，再按块边界向源站补齐缺失部分；若其他下载已覆盖请求范围，就共享在途数据。拼接前检查文件总长与实体标签 ETag，避免把不同版本的内容混成一个响应。

实际影响：编辑判断：分发模型权重或大视频的网站可减少反复调分段大小的工作，同时让多个读取复用下载。R2 首字节延迟高分位约减半是厂商内部结果，不能直接推算其他站点收益。

限制与来源：源站必须支持字节范围，原本不可缓存的响应不会因开启此项而变得可缓存。小请求仍可能读取整个缓存块；遇到无法安全拼接或解压转换的情况会返回完整内容。

02 · Transit Gateway 与 Cloud WAN：用双向地址转换连接重叠网段

事件简介：AWS 为 Transit Gateway 和 Cloud WAN 的网络连接附件增加托管一对一 NAT，即把一个私有地址映射到另一个地址。它针对并购、合作伙伴接入或多云互联时，双方都使用相同 IP 网段、无法直接互通的问题。

技术机制：服务通过 Regional Private NAT Gateway 集成，在附件上声明源网段及其映射到的不重叠地址范围，自动处理两个方向的转换，不必再单写返回流量规则。范围覆盖 VPC、站点 VPN、Direct Connect 以及经 Transit Gateway Connect 接入的 SD-WAN 设备。

实际影响：编辑判断：两家公司都使用 10.0.0.0/16 时，可先转换一侧地址再互连，减少给原有机器重新编号或自建 NAT 设备的改造。团队可用控制台、CLI 或基础设施模板配置，并通过 CloudWatch 指标和 EventBridge 事件监控。

限制与来源：公告限定在这两项服务运营的商业区域，费用须查 VPC 定价；没有提供业务切换耗时或独立性能测试。“几分钟配置”是厂商描述，实际应用连通仍应验收。

09 · PQ GeoKey Manager 封闭测试：密文全球分发，解封能力留在区域内

事件简介：Cloudflare 推出后量子 GeoKey Manager 封闭测试，计划 2027 年第一季度正式可用。它面向有数据地域要求的组织，把客户私钥加密包装后全球分发，只允许选定区域的服务器解封，同时应对“先收集密文、以后用量子计算解密”的威胁。

技术机制：区域根密钥派生按服务区分的应用密钥，包装方案组合 ML-KEM-768 与 X25519 两类密钥封装机制。服务器凭硬件身份及机房清单取得授权区域根密钥；缺少所需密钥就拒绝启动或拒绝请求，不转往其他地区解封。

实际影响：编辑判断：处理敏感流量的团队可把“密文存在哪里”和“哪里能使用私钥”分开设计。这样能全球复制包装密钥，同时把解封权限限定在区域边界，减少逐个客户密钥重包来适应服务器变化的需求。

限制与后续观察：该机制不决定流量路由、隧道终点或明文处理位置；CDN 的新集成仍在开发。根密钥管理与分发服务仍处于信任边界内。应跟踪正式开放、CDN 迁移测试及区域故障演练，验证限制是否可操作、可持续。
