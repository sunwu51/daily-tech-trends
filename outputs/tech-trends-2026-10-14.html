窗口内工程披露 · Cloudflare · 10 月 13 日

D1 控制面：把百万数据库的元数据管理移出查询热路径

事件简介：Cloudflare 披露基于 SQLite 的托管数据库 D1 如何支持大量小数据库。多租户平台按用户、应用或预览环境建库，会使创建与路由元数据规模迅速增长；文章介绍内部架构调整，并非当天推出一种新数据库。

技术机制：每个数据库由一个带 SQLite 存储的 Durable Object 承载，中央 Postgres 保存权威元数据，Workers KV 保存边缘路由映射。SQL 请求通常经 Eyeball Worker 直接到目标对象；映射缺失时才通过 Hyperdrive 缓存和只读副本回查。对象以带随机抖动的约 30 秒心跳校正创建、删除状态。

实际影响：编辑判断：给每个客户建独立库的 SaaS 团队可借鉴这一拆分，把低频管理操作与高频查询分开，避免所有 SQL 都争用中央元数据库；失败的创建也能靠心跳清理孤立对象。

限制与来源：KV 与心跳采用最终一致性，状态传播并非瞬时完成；缓存失效仍有回查路径。规模与增长数据来自厂商，不能据此推断任意查询负载都能线性扩展。

窗口内官方发布 · AWS · 10 月 13 日

ECS LiveTaskCount：扩缩容时把仍在工作的任务纳入计数

事件简介：Amazon ECS 新增免费服务指标 LiveTaskCount，并取消 Container Insights 中 RunningTaskCount 的指标收费。ECS 的任务是运行容器的调度单元；在缩容时，任务虽已准备停止，却可能仍在排空连接、继续产生负载指标。

技术机制：LiveTaskCount 覆盖 ACTIVATING、RUNNING、DEACTIVATING 等期望状态下仍活跃的任务，包括停止过渡期。原 RunningTaskCount 要求当前与期望状态都为 RUNNING，两者统计口径不同；新指标属于 ECS 服务利用率指标，无需启用 Container Insights。

实际影响：编辑判断：按每任务请求量制定扩缩容策略的运维团队，可检查分母是否漏掉排空连接的实例，再选择合适口径，减少过渡期容量判断偏差。原指标继续适合观察稳定运行任务的健康状态。

限制与来源：公告称覆盖全部 ECS 区域；RunningTaskCount 的免收费从 10 月 1 日自动生效，但只针对该指标，不能理解为整个 Container Insights 免费。未公布自动扩缩容策略的实测收益。

xtool：从 Linux 或 WSL 构建并签名安装 Swift iOS 应用

简介：xtool 面向希望在 Linux、Windows 的 WSL 环境或 macOS 开发 iOS 应用的 Swift 开发者。它把 SwiftPM 包构建成应用，再完成签名和真机安装；Windows 路径使用 Linux 子系统，不能理解为所有功能都原生运行于 Windows。

技术特点：setup 从 Xcode.xip 提取 iOS Swift SDK；项目用 xtool.yml 指定 Bundle ID 和打包信息，Build Server Protocol 向编辑器提供构建上下文。运行 xtool dev 后，SwiftPM 编译，工具连接 Apple Developer Services 生成证书与配置描述文件，再通过 USB 安装到设备。

适用场景与价值：编辑判断：主要使用 Linux 的开发者可在熟悉的编辑器修改 SwiftUI 示例，重复构建并装到自己的 iPhone，减少在另一台开发机器上手工完成打包、签名和安装的步骤。

限制与来源：当前指南要求 Swift 6.4、Xcode 27 下载和 Apple 身份；免费账号的密码登录依赖私有 API，API Key 路径需付费开发者会员。Linux 需 usbmuxd，WSL 还需 USB 转发，并未消除 Apple SDK 与设备信任条件。

Nightingale：在现有指标、日志与 SQL 数据源上统一告警

简介：Nightingale（夜莺）是可自托管的告警平台，面向已有 Prometheus、Loki、ClickHouse 等系统的运维团队。它查询现有数据、判断规则、处理事件并把通知送到 Slack 或 PagerDuty，不要求先迁走监控存储，也可继续使用 Grafana 看图。

窗口内工程披露 · Cloudflare · 10 月 13 日

Cloudflare 数据管道：先缩减数据，再承担跨区域冗余

事件简介：Cloudflare 总结从春季到秋季的数据管道改造。全球事件原先在源端发送两份到中央区域，流量增长使骨干网络与接收器负担持续增加；本次文章披露迁移过程和结果，并非当天全部上线。

技术机制：Logfwdr 先把事件发送到一个可用接收区域，经抽样和 Buftee 缓冲后再复制到另一处 ClickHouse。管道还把抽样与部分聚合前移：同一键的计数、求和在源端、接收端和写入端逐步合并，降低传输量；区域断连后由缓冲保留数据供追赶。

实际影响：编辑判断：运营跨区域分析系统的团队，可先确认哪些查询只需汇总值，再比较前移聚合和晚复制的收益，避免为了冗余在最昂贵的长距离链路上重复发送全部原始事件。

限制与来源：抽样返回估计值，聚合只能精确回答事先选定维度的问题，两种方式不能互换。约 70 GB/s 压缩流量节省是厂商特定数据集的总结果，不是每套日志系统都能获得的比例。
