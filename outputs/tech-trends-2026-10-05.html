Ponytail：让编码 Agent 先做最小必要改动

简介：Ponytail 是给 Claude Code、Codex、Cursor 等编码 Agent 使用的插件式技能，服务希望减少过度实现、同时保留校验与安全护栏的开发者。它在 Agent 写代码前引导其阅读实际调用路径，再按“无需新增、复用现有代码、标准库、原生能力、依赖、最后才自定义实现”的阶梯选择方案。
技术特点：项目把 YAGNI（只实现确有需要的部分）写成可安装技能，并通过生命周期 hook 接入多个 harness；README 的基准用真实 FastAPI+React 仓库和 12 个任务比较带技能与不带技能的 diff、token、成本和耗时。作者报告平均少 54% 行代码，但仍保持 100% 安全检查通过。
适用场景与价值：做表单、日期控件或小型 API 改动时，Agent 会优先使用 HTML 原生能力或仓库已有组件，减少安装依赖和维护代码；团队可把这套决策顺序作为默认工作流，再审阅最终 diff。限制与来源：基准由项目作者运行，样本为 Haiku 4.5、12 个任务，不能代表所有模型；插件 hook 需要 Node.js，且仍依赖 Agent 正确理解需求。来源：README 的机制、基准与安装说明。
来源：https://github.com/DietrichGebert/ponytail

e2e：用自然语言驱动 Web 与移动端端到端测试

简介：tester-army/e2e 是面向 Web 和移动应用的端到端测试框架。测试作者用自然语言描述目标，Agent 操作应用，再用 locator 和断言验证结果；适合需要覆盖复杂用户流程、但不想为每一步都编写点击脚本的团队。
技术特点：TypeScript SDK 把 app、agent、screen 注入测试上下文；agent.act 执行语义动作，agent.assert 记录可复核的检查。带 Agent 步骤的动作会被记录，后续应用未变化时可重放而不再调用模型；Web 引擎基于 Playwright，移动端使用模拟器/仿真器，模型可自带 API 或本地运行。
适用场景与价值：结账、升级套餐等跨页面流程可先用目标描述快速建立覆盖，再以稳定 locator 断言关键状态，减少纯脚本在 UI 变化后的维护。限制与来源：项目仍在 1.0 前的活跃开发阶段，API 可能在小版本变化；CLI 默认发送匿名使用数据，可关闭；自然语言动作仍需检查模型误操作。来源：README 的 Quick start、Packages、Telemetry 与 Status。

text-to-cad：把 CAD、工程图和机器人描述做成 Agent 技能

简介：text-to-cad 不是单一建模应用，而是一组面向编码 Agent 的工程技能，输入自然语言或图片请求，输出 STEP 为主的 CAD 模型，也可导出 STL、3MF、GLB、DXF、URDF、SRDF 和 SDF。它服务机械设计、3D 打印、机器人和制造审核工作流。
技术特点：仓库按技能拆分 CAD、STEP 零件检索、工程图、机器人描述、G-code、DFM/DFAM 等目录；运行时通过 uv/ cadgen 和 OpenCascade、build123d 生成或检查几何，并提供本地 CAD MCP 与查看器。技能文件把尺寸、孔位、材料和制造规则写成可复核步骤，而不是只返回网格。
实际影响与限制：工程师可让 Agent 先生成带参数的 STEP，再调用 DFM 或 SendCutSend 检查后交给加工厂，减少在多个工具间手工转换。仍待观察：Windows Smart App Control 会阻止未签名 OCP 原生模块，部分功能依赖本地 CAD 环境和 pinned cadgen；后续应验证复杂装配的几何正确率、规则覆盖和匿名分析开关。来源：README 的 Skills、Installation、Usage analytics 与 Windows 限制。

Netflix：用工作负载证明把云 IAM 身份换成内部短期证书
