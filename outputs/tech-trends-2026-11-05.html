01 · Go JSON v2 正式可用：把语法流处理与类型映射分开

事件简介：Go 官方宣布 encoding/json/v2 与 encoding/json/jsontext 在 Go 1.27 稳定并正式可用。JSON 是程序间交换数据的文本格式；新版解决旧接口难以严格检查输入、递归解析重复做功的问题，旧包仍将持续受支持。

技术机制：jsontext 负责读写词元和完整 JSON 值，v2 再负责与 Go 类型映射。自定义类型可用 MarshalJSONTo、UnmarshalJSONFrom 直接接流式编码器，减少先生成整段字节再校验、重解析的环节；默认拒绝重复字段名和无效 UTF-8。

实际影响：编辑判断：维护大型嵌套配置解析器时，可逐步改写自定义方法，并用选项保留确实依赖的旧行为，减少一次性迁移所有调用点的工作。安全入口也能明确拒绝有多种解释的重复字段。

限制与来源：空切片、大小写匹配与 omitempty 等语义有变化，不能只换导入路径就假定输出相同。解码最高十倍加速是官方基准，编码速度大致相当；不能推定整个应用都同幅提速。

02 · Cloudflare 细分个人代理访问策略：先看路径，再决定放行范围

事件简介：Cloudflare 为代用户浏览、比较商品或操作网站的个人代理增加流量分析和细分访问策略。站点现在可在 Security Analytics 单看 Personal Assistants，按代理查看请求数、路径、状态码和来源网络。

技术机制：访问策略可先设置总体 Agents 规则，再对受支持代理分别选择允许、不允许访问含广告页面或完全阻止。账户滥用防护的早期访问功能还能关联用户账户与代理活动，通过哈希用户标识设置防火墙规则，处理特定账户。

实际影响：编辑判断：电商团队可先判断代理在商品页、登录还是结账环节遇到错误，再调整对应访问决策，减少将所有自动流量一并阻挡后失去正常客户的情况。

限制与来源：细分策略只针对受支持代理；账户关联依赖仍在早期访问的 Account Abuse Protection。识别代理不等于知道用户授权、订阅或信誉，文章把这些列为后续工作，不能将允许访问等同于认可交易授权。

03 · ECS 托管守护任务可读容器日志文件：复用现有采集代理

事件简介：AWS 为 ECS Managed Instances 增加 json-file 日志驱动，并为 Managed Daemons 增加日志卷。应用容器可把日志写成 Docker 标准 JSON 文件，再由每台实例上的一个托管守护任务统一采集、转发。

技术机制：应用任务定义在 logConfiguration 选择 json-file；守护任务定义用 logDriverVolumeConfiguration 声明卷，再经 mountPoints 挂入容器。读取这些文件无需指定宿主绑定路径或取得 root 权限，每个容器以自身 ID 建独立目录。

实际影响：编辑判断：已有文件采集型观测代理的团队，可沿用解析与转发配置，把同机多容器日志接入既有目的地，减少为每个应用单独改采集链路；容器目录也保留了追溯来源的线索。

限制与来源：仅覆盖同时提供这两种托管能力的商业区域，功能不另收费。文件保留到容器移除为止，不能把本地文件当长期归档；公告也没有给日志不丢失、下游存储免费或采集开销的保证。

04 · RDS Oracle 跨区复制快照：在同一请求带上选项组

事件简介：Amazon RDS for Oracle 允许跨区域复制数据库快照时，同时复制关联选项组。选项组保存数据库扩展功能配置，具有区域边界；此前管理员先复制快照，再到目标区域重建组，之后才能恢复。

技术机制：现有 CopyDBSnapshot API 与命令行中的 CopyOptionGroup 布尔参数扩展到跨区场景，设为 true 即请求一并复制；原有跨账号复制场景也继续支持。改变的是备份关联配置的搬运步骤，而非数据库持续同步。

实际影响：编辑判断：准备异地恢复演练时，可把快照与其功能配置放在同一复制请求中，减少手工重建选项组时遗漏设置的操作。此项关注恢复所需配置，与本周快照费用细分、存储自动扩容是不同变化。

限制与来源：公告范围为 RDS Oracle、全部商业区域及美国 GovCloud。它未承诺整个恢复流程自动完成，也未列恢复时长或所有选项的跨区兼容细节；仍需在目标区域完成实际恢复验收。

07 · Worktrunk：为新工作树带入可独立修改的构建缓存

简介：max-sixty/worktrunk 是管理 Git 工作树的命令行工具，面向同时处理多条代码修改的开发者。工作树是同一仓库的独立检出目录；工具按分支名计算目录路径，提供创建、切换、状态查看和清理流程。

技术特点：创建后的钩子可运行 wt step copy-ignored，把被 Git 忽略的依赖及构建缓存带入新目录。支持 reflink 的文件系统让两个文件先共享磁盘块，任一侧写入时再复制；.worktreeinclude 可限定复制对象，已跟踪文件不受触碰。

适用场景与价值：编辑判断：Rust 项目开第二条修复分支时，可复用 target 中已编译依赖，同时让后续写入分开，减少新目录从头构建的等待。这里关注缓存预热，区别于本周 Docker 指南的挂载位置与 Git 元数据交接。

限制与来源：ext4、NTFS 会退回完整复制，耗时仍随文件数量增长；Python 虚拟环境含绝对路径，文档要求用 uv sync 重建。默认复制所有忽略文件，应用包含清单筛选；工作树不提供进程或网络隔离，作者速度示例未经复测。

09 · Auto Ontology：先审定业务术语，再让代理生成可核查 SQL

简介：NVIDIA/auto-ontology 为企业数据库建立语义层，即把业务术语、指标口径和表关系映射到真实字段。它服务于自然语言查数与数据代理，提供网页、命令行、接口及 MCP 工具协议接入，补充已有语义模型。

技术特点：采集服务读取表结构、列特征与样本，推断连接及指标 SQL，写入 Postgres 与 pgvector 向量索引。人审定术语和表达式后，代理检索候选、生成 SQL、核对过滤值并修复失败查询，返回结果、SQL 和步骤；数据不足时先检查能否回答。

适用场景与价值：编辑判断：多个团队查询“收入”时，可复用已审定表达式及关联路径，减少每次让模型重新猜指标含义，也给业务人员留下可对账的查询依据；人审不是可省略的准备步骤。
