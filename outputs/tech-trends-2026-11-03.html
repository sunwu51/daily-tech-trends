01 · Cloudflare DNS 定向构建：只重算能证明需要更新的部分

事件简介：Cloudflare 披露 DNS 构建流水线改造。DNS 区域保存一个域名的记录与设置；某些设置变化过去会重建整个区域，大客户数千万条记录因此反复加载。本次新材料解释怎样缩小计算范围，并非新的 DNS 协议。

技术机制：事件携带变更字段，规划器选择只更新指定名称、名称加共享元数据或完整区域；执行前重读数据库，避免排队期间状态改变。调度器合并同一区域的工作，Kafka 消息在此前任务全部完成后才推进确认位置，优先允许重做而不丢变更。

实际影响：编辑判断：维护配置发布系统时，可借鉴“目标输出须与全量构建逐字节一致”的验收方式。作者用生产流量镜像比较输出，报告峰值内存从 79 降至 12 GiB，进一步缩短等待后，中位构建延迟由约 7.7 降至 3.3 秒。

限制与来源：延迟只到写入 Quicksilver，不含全球分发，也不是单个区域的承诺。未知变更通常仍全量构建；超大区域因无法完成全量构建而有例外，罕见情况需人工重建名称。数字为 Cloudflare 自报。

07 · Docker Sandbox 工作区指南：代码放在哪里，决定如何交接结果

事件简介：Docker 发布沙箱代码布局指南，区分共享宿主检出、任务独立工作树，以及把仓库完全留在沙箱内的方式。新信息是文件、依赖与 Git 操作的具体交接边界，区别于本周虚构漏洞案例中的审查输出核验。

技术机制：直接挂载让编辑器即时看到代理修改，但切换分支也会改变代理正在处理的文件。只挂载链接工作树时，其 .git 指向挂载外元数据，沙箱内不能正常做 Git 操作；clone mode 则把宿主源只读挂载，再建立具有自身元数据的独立克隆。

实际影响：编辑判断：需要边改边预览时可共享检出；希望代理自行管理分支时，可用独立克隆，审阅后取回已提交分支。这样把并行任务的文件变化分开，减少人工编辑和代理改动互相混入，但仍须协调共享服务与工具。

限制与来源：共享目录中的原生依赖可能在 Linux 沙箱与宿主系统间不兼容。无挂载模式需发布端口才能预览服务，删除沙箱会丢失只存在其中的文件；分支本身不能隔离同一目录的同时编辑。

10 · Instrumentation Hub 正式可用：自动注入 SDK 仍须核对重启行为

事件简介：Grafana Cloud 将 Instrumentation Hub 转为正式可用，并增加选择性 OpenTelemetry SDK 注入。它先发现 Kubernetes 中的服务，再按范围接入遥测；本项关注采集部署，区别于近期代理质量评估与仪表盘配置。

技术机制：界面选择经 Fleet Management 下发到 Alloy，写成按命名空间、标签匹配的规则。Pod 创建时，准入 webhook 挂载 SDK，并用 LD_PRELOAD 等启动变量加载到进程；Beyla 的内核侧 eBPF 观测与进程内 SDK 配合，避免重复产生指标。

限制与后续观察：仅限 Linux Kubernetes，SDK 支持 .NET、Java、Node.js、Python；冲突的 LD_PRELOAD、自带 SDK 或原生编译应用等会被跳过。应跟踪不同运行时的兼容、滚动替换时延与实际遥测覆盖；注入器失效时放行 Pod，不代表 SDK 已成功注入。
