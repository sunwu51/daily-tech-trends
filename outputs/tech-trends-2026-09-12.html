当前 Trending / 空间数据

God's Eye View：浏览器中的实时地球数据模拟器

简介：这是一个本地运行的开源浏览器应用，把飞机、船舶、卫星、地震、交通和公共摄像头等公开信号叠加到写实 3D 地球，面向空间数据探索、教学和原型开发。

技术特点：每类馈送以独立模块接入 3D globe，可点击目标跟踪、绘制轨迹并切换 CRT/NVG/FLIR 等 GLSL 传感器效果；语音控制是可选的实时 AI 代理。项目支持 Pinokio 或 Node.js 24/26 本地启动，基础图层无需 API key。

适用场景与价值：研究者可以先在一个场景检查多类公开信号，再决定要不要接入 Cesium 或 Google 的付费密钥，省去先搭采集与渲染脚手架的工作。

限制与来源：交通为真实道路上的聚合模拟，摄像头姿态和发射轨迹是粗略估计；数据覆盖、第三方条款和密钥配额仍由各提供方决定。来源：官方 README

当前 Trending / Agent Harness

CowAgent：可持续运行的个人 AI 助手

简介：CowAgent 是开源的 Agent Harness，服务希望在个人电脑或服务器上长期运行助手的用户。它能规划任务、调用文件和终端工具、管理技能，并接入 Web、微信、飞书、Telegram 等渠道。

技术特点：架构把 Channel、Agent Core、三层记忆（上下文/每日/核心）、知识库和工具分开；记忆支持关键词与向量混合检索，知识会整理成 Markdown wiki，多代理可按角色、模型和技能协作。模型提供方可在 Web 控制台切换。

适用场景与价值：个人研究或团队值班可让同一助手跨聊天渠道继续任务，并把重复操作沉淀成技能和长期记忆，减少每次重新解释背景的成本。

限制与来源：README 说明它是参考实现，长期运行仍需自行配置模型凭据、权限和部署；“自我进化”没有给出独立效果基准。来源：官方 README

当前 Trending / 文档知识库

LLM Wiki：增量维护的个人知识库

简介：LLM Wiki 是跨平台桌面应用，把 PDF、Office、EPUB、图片、网页剪藏和 URL 批量摄取为互相链接的 wiki，面向需要长期整理研究资料的个人和小团队。

技术特点：摄取分为“分析后生成”两次 LLM 调用，并用 SHA256 缓存跳过未变化文件；页面带 YAML frontmatter 和 wikilink，知识图谱结合直接链接、来源重叠、Adamic-Adar 与类型亲和度，另有 LanceDB 向量检索和可恢复队列。

适用场景与价值：研究者把资料放入 sources 文件夹后，应用可持续同步新增、修改和删除，并保留来源追踪；这把每次临时 RAG 查询转成可审阅、可迁移的资料库。

限制与来源：向量搜索、深度研究和云模型依赖额外服务；LLM 生成页面仍需要人工 Review，项目没有证明知识图谱准确率。来源：官方 README

当前 Trending / AI 网关

Higress：统一治理 LLM 与 MCP 的云原生网关

简介：Higress 基于 Istio 与 Envoy，面向要把模型 API、传统 API 和 MCP 工具放在同一入口治理的平台团队。它支持 Docker 或 Kubernetes 部署，并提供控制台。

技术特点：网关可用 Go、Rust 或 JavaScript 编写的 Wasm 插件扩展；README 明确支持主流模型提供商，并可通过插件托管 MCP Server，配合 openapi-to-mcp 将 OpenAPI 规范转换成远程 MCP 服务。

适用场景与价值：平台团队可以先在网关统一鉴权、限流和路由，再把已有 OpenAPI 服务逐个暴露给代理，避免每个 AI 应用单独实现代理层。

限制与来源：项目仍是 CNCF Sandbox，插件隔离、跨区域延迟和高并发基准需要部署方验证；镜像仓库按区域配置。来源：官方 README

窗口内 / 容器编排

Kubernetes v1.37：原生直方图进入 Beta

事件简介：Kubernetes 官方宣布 Native Histograms 在 v1.37 达到 Beta，监控系统可以更直接地表达延迟等分布，而不必只依赖固定 bucket。

技术机制：该能力沿 Prometheus/OpenMetrics 的原生直方图语义推进，允许客户端和采集链路保留更丰富的分布信息，再由查询端按需要计算分位数。

适用场景与价值：延迟长尾明显的服务可减少为每个业务预先猜 bucket 的工作，容量和 SLO 分析也能基于同一分布数据进行；升级前应检查监控后端兼容性。

限制与来源：Beta 不等于所有采集器和存储后端默认启用，生产部署需按 v1.37 文档验证版本与资源开销。来源：Kubernetes Blog

窗口内 / DNS 安全

Cloudflare 1.1.1.1 开始验证后量子 DNSSEC

事件简介：Cloudflare 宣布 1.1.1.1 可验证使用 NIST 标准 ML-DSA-44 的 DNSSEC 签名，为 DNS 迁移到后量子签名提供大规模运行试验。

技术机制：ML-DSA-44 签名约 2,420 字节，远超常见 UDP 预算；解析器需要在截断后转 TCP 等传输，并在传统与后量子算法并存时避免降级到较弱签名。

适用场景与价值：权威 DNS 和解析器运营者可据此测试大 DNSKEY 响应、TCP 重试、缓存和双算法验证链，为未来更换密钥提前暴露网络设备假设。

限制与来源：这是 Cloudflare 的递归解析实践，不表示权威 DNS 已普遍支持；量子计算威胁尚未现实，迁移仍需生态协调。来源：Cloudflare Blog

窗口内 / 编码代理

GitHub Copilot app：把 diff、终端和浏览器放在同一任务

事件简介：GitHub 介绍 Copilot app 的并排工作区，让用户在同一会话中审阅代理 diff、运行项目命令并打开浏览器预览。

技术机制：diff 面板显示增删并允许评论或要求修改，终端面板可运行脚本和多个窗口，浏览器面板支持 Pick & Polish 选择页面元素继续迭代，形成生成—验证循环。

适用场景与价值：修复前端缺陷时，开发者可先看补丁、运行测试、刷新页面再决定是否接受变更，减少在编辑器、终端和浏览器间切换的上下文损失。

限制与来源：功能和终端权限随账户及版本变化；并排面板改善验证路径，但不能替代代码审查、沙箱和最小权限。来源：GitHub Blog

窗口内 / Kubernetes Alpha

Kubernetes：原地扩容触发同节点抢占

事件简介：v1.37 新增 Alpha 特性，在运行中 Pod 的原地扩容因节点无余量而进入 Deferred 时，让调度器为高优先级工作负载释放同节点容量。

技术特点：开启 InPlacePodVerticalScalingSchedulerPreemption 后，kube-scheduler 持续跟踪 Deferred 条件，只在当前节点选择低优先级受害 Pod 并优雅驱逐，不重新为原 Pod 选节点。

适用场景与价值：集群可以更激进地装箱批处理任务，同时让突发流量的关键服务在不重启的情况下获得 CPU 或内存；后续应观察抢占时延和业务抖动。

限制与来源：这是 Alpha、默认关闭且仅限单节点边界；需验证优先级策略、驱逐预算和失败恢复。后续证据应包括真实集群指标与升级兼容性。来源：Kubernetes Blog
