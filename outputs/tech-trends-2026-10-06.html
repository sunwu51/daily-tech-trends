openGym：把健身记录放回自己的服务器

项目简介：openGym 是自托管的健身与自重训练记录应用，面向希望掌握数据而不依赖订阅服务的个人。它用 Docker Compose 启动，支持手机和电脑同步、离线使用、Passkey 登录，也提供 Android 应用；训练计划、组数、体重和进步数据保存在用户控制的目录。
技术特点：前端是 React 19/Vite，API 使用 Node 的 node:http，数据以 JSON 文件存储；nginx 把前端和 /api 放在同一来源以满足 Passkey 要求。同步采用带服务器版本号的乐观并发：冲突时返回最新文档，设备合并后重试；可导入 FitNotes、Strong、Hevy，并提供可选的本地 AI 教练和只读 MCP。
适用场景与价值：个人或小型训练团队可以用 docker compose up -d 建立私有记录库，手机离线训练后再同步，而不必把历史交给第三方。JSON 文件和导出功能也让备份、迁移和复盘更直接。限制与来源：首次启动要下载约 140 MB 媒体；Passkey 远程访问需要 HTTPS，iOS 不能直接侧载原生应用；AI 教练默认可选且仍依赖外部模型密钥。
来源：https://github.com/DuarteSantos8/openGym

Redshift 把 Iceberg 物化视图带到开放数据表

事件简介：AWS 在 10 月 5 日宣布 Amazon Redshift 可创建并刷新存储为 Apache Iceberg 表的物化视图。它针对反复执行昂贵连接和聚合的数据分析场景，把一次计算结果放进 S3 或 S3 Tables，并登记到 Glue Data Catalog。
技术机制：通过 CREATE MATERIALIZED VIEW ... USING ICEBERG 创建视图，Redshift 支持手动增量刷新，只重算发生变化的部分。结果是标准 Iceberg 表，可被 Athena、EMR/Glue 上的 Spark、Trino 或 Snowflake 直接查询，也能按需装入 Redshift Managed Storage 供高性能仪表盘使用。
实际影响与限制：数据团队可以让 Redshift 负责一次物化，让多个引擎共享同一份开放结果，减少复制、转换和跨引擎编排。限制与来源：功能要求 Redshift Serverless 或支持的 Graviton 区域，刷新是手动增量方式；分区、更新频率和跨引擎语义仍需按文档与实际工作负载验证。

Bedrock 上线 GLM 5.3，加入长上下文与提示缓存

窗口内官方工程文章｜Kubernetes，2026-10-05 · Kubernetes Blog

Kubernetes 用 NVMe Swap 提高 Agent 沙箱密度

事件简介：Kubernetes 博客介绍了 v1.34 已经 GA 的节点 Swap，并用本地 NVMe SSD 为突发、间歇运行的 Agent 沙箱释放内存。文章针对浏览器、CI 构建和隔离 Python 运行时中“启动时占内存、空闲时仍驻留”的问题。
技术机制：在 cgroup v2 的独立 swap 记账下，kubelet 配置 failSwapOn: false 与 memorySwap: LimitedSwap，把匿名内存分页到高速本地盘。作者在 gVisor Python 沙箱测试中把并发数从 80 提到 240，在 gVisor Chrome 中从 80 提到 160；活跃工作集过度换出仍会造成 I/O 等待。
实际影响与限制：运行不可信代码的集群可以用 Burstable QoS 和高速本地盘吸收空闲内存，减少为峰值预留的 RAM。限制与来源：Swap 是突发缓冲，不是活动内存替代品；基准来自特定 GKE 节点、运行时和工作负载，实际延迟、磁盘耐久性与云厂商支持需单独测试。
来源：https://kubernetes.io/blog/2026/10/05/scaling-kubernetes-workloads-with-node-swap/
窗口内官方发布｜GitHub，2026-10-05 · GitHub Blog

ReviewBench：让 AI 代码审查有可复现的离线基准

事件简介：GitHub 发布 ReviewBench，用真实 Pull Request 的分布来评估代码审查 Agent。它回应了不同审查器在发现数量、噪声、严重性和精确率之间难以比较的问题。
技术机制：基准按超过一亿个 GitHub PR 的语言、仓库规模和改动规模建模，使用多来源黄金标注集、统一评分规则，并按严重性、类别和 precision/recall 偏好拆分结果。GitHub 称资深工程师独立验证了标注，并发现离线结果能较好预示 Copilot Code Review 的生产实验方向。
实际影响与限制：团队可以先在离线样本上比较自研审查器，再决定是否接入合并流程，减少只凭演示或单一命中率选型。限制与来源：黄金集和验证过程由 GitHub 主导，不能替代团队自己的代码类型、语言和误报成本评估；上线前仍应以真实 PR 和人工复核校准阈值。

AnyPS5：把 PS5 可执行文件重链接到 Linux/Windows

简介：AnyPS5 是面向互操作、研究和保存的 PS5 可执行文件移植工具，目标平台为 Linux 和 Windows。它不运行独立模拟器进程，而是尝试把程序转换为目标系统格式，并实现所需的系统库。
技术特点：核心 relinker 负责转换可执行文件，core/libs/prx 提供可动态链接的系统 PRX 库；着色器重编译器可生成经 SPIR-V Tools 校验的 SPIR-V。控制器输入通过 SDL 映射，也可用 anyps5-input.ini 配置键鼠；仓库公开已验证游戏和库函数进度。

窗口内近期研究｜EdWorkingPaper，2026-08 · Brown Annenberg Institute

两年学校实验：AI 家教的效果受使用频率约束

事件简介：EdWorkingPaper 发布一项在田纳西州 18 所初中的两年集群随机试验：学生在日常补救数学课中使用被配置为“教练而非直接给答案”的 Khanmigo。研究报告每学期数学成绩提高 1.3 个全国百分位，全年主动参与的估计效果为 0.14 个标准差。
技术机制：研究把学生随机分配到使用 Khan Academy 加 Khanmigo 的组别，并跟踪练习与对话行为；96% 的学生至少试用一次，但中位数学生只在约三分之一的练习日发消息，在出错练习中仅 17% 触发对话。多数消息是直接答案或点击建议提示，说明“可用”没有自动转化为深入辅导。
适用场景与价值：学校评估 AI 辅导时应同时测量学习成绩、实际使用和对话质量，不能只看账号开通率。仍待观察：这是单项美国数学干预，论文指出收益接近无 AI 的 Khan Academy 练习，后续需要不同年级、学科和更高参与度方案的复现实验；来源：研究摘要与 DOI。
