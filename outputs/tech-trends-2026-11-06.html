01 · FileCodeBox：用取件口令交付临时文件

简介：vastsa/FileCodeBox 是可自托管的文件与文本分享工具，面向临时交付资料的人。发送者无需注册，上传后取得口令，接收者输入口令取件；服务可用 Docker 启动，数据目录挂载到宿主保存。

技术特点：FastAPI 后端与 Vue 3 界面把文件、文本放进同一分享流程，支持分片上传，并按时间或取件次数失效、清理。存储可用本地、S3、OneDrive 或 WebDAV；兼容 MCP 工具协议的客户端还能调用 share_text、share_file 创建分享。

适用场景与价值：编辑判断：给外部协作者交付一次性日志包时，可设置取件次数与保存时长，减少创建账户、发完后再手工清理文件的步骤；存储仍由部署方选择和管理。

限制与来源：安全文档默认单文件上限为 10 MiB，可配置；首次启动须设置管理员密码。MCP 默认不要求 Token，关闭游客上传或启用 Token 校验后才要求凭证，公开部署须明确这一入口的访问设置。

02 · LZ4：把压缩速度与压缩比的取舍显式交给调用者

简介：lz4/lz4 提供无损压缩算法的 C 参考库与命令行程序，面向需要快速压缩、解压文件或数据流的开发者。它可通过 Make 构建，也提供 CMake、Meson、Visual Studio 路径；本项是项目发现，不是版本发布。

技术特点：调用者可提高 acceleration 因子，用压缩比换取压缩速度；LZ4_HC 则多花压缩端 CPU，争取更小结果。长数据流拆成多个块，再放入 frame 帧格式；跨实现互通需要遵守帧规范，不能只约定裸块算法。字典输入仅使用末尾 64 KB。

适用场景与价值：编辑判断：日志传输链路若更在意接收端解压开销，可用自身样本比较普通与 HC 模式，在发送端多做计算、保持相同解码路径；小消息也可测试共同字典，减少重复内容占用。

限制与来源：README 基准注明处理器、编译器与语料，速度不是任意业务保证。库采用 BSD 2-Clause，命令行采用 GPL-2.0-or-later；嵌入库与分发程序需分别核对许可。压缩比也必须用实际数据验收。

06 · GhostMap 调查：资源解析分歧可让 Android 陷入反复崩溃

事件简介：Bitdefender 披露 GhostMap：特制 Android 安装包即使不含可执行代码、不申请权限，也可在系统自动读取资源时触发持续崩溃。最初野外样本只导致安装失败；反复崩溃版本是研究者后续复现，不能写成已发生的大规模攻击。

技术机制：APK 使用 ZIP 容器。两个系统库对非常规压缩方式分类不一致，使声明长度绕过边界检查，随后按这个长度映射文件；读取超出真实文件范围的区域会触发 SIGBUS 原生错误，杀死进程。若读取者是 system_server，重启后再次读取便形成循环。

实际影响：编辑判断：维护安装包扫描流水线时，应把结构校验放在调用系统解析器之前，并隔离解析进程，避免一个异常包拖垮整个扫描任务。问题说明“没有执行代码”也不等于解析输入安全。

限制与来源：研究方报告复现覆盖 Android 10 起的版本，并列出 Pixel 10、Android 17 的具体构建；这些不是全设备普查。其称发表时无修复、Google 未按安全更新处理，均为研究方披露；故障属于拒绝服务，未证明代码执行或数据窃取。

08 · Rubicon 私测：把 Git 对象存储与引用事务分开扩展

事件简介：GitHub 披露新 Git 存储架构 Rubicon，目前仅有限私测，计划明年初扩大推出。它针对大量代理并发向不同分支推送的负载，把服务请求的计算节点、持久数据与后台维护拆开，避免所有工作都跟着完整仓库副本扩展。

技术机制：Git 对象包放入 Azure Blob Storage；引用与包清单存入 Ref-CAS 复制日志服务。写入先持久保存对象包，再以比较并交换事务更新引用，只锁涉及的引用；读取先比较日志序号，落后时再拉所需数据。独立压实节点合并包，发布前校验对象集合一致。

实际影响：编辑判断：大型仓库可借这一分工分开增加读写节点与维护节点，减少垃圾回收、包合并抢占在线 CPU 的影响；本地盘可重建为缓存，不再承担唯一持久副本职责。

限制与后续观察：每秒数万次引用事务等数字是 GitHub 自报，不代表完整端到端推送吞吐。单对象读取、部分副本等仍列为后续优化；应观察扩大上线后的尾延迟、故障恢复与压实积压数据，再判断真实负载下能否持续保持性能。

09 · Google Skills 的 TPU 排障流程：先查容量被谁占用

简介：google/skills 是 Google 产品与云技术的代理工作流集合。本项观察其中 GKE TPU 预留容量排障技能，服务于已有加速器预留、却无法创建或扩展节点池的运维人员；它是可安装的诊断指引，不是新的集群调度器。

技术特点：流程先比较预留总数与 inUseCount，再沿虚拟机标签找回所属集群和节点池，结合 Ready 状态与自动修复设置定位占用者。共享预留需检查拥有者项目，并区分健康任务占用与异常节点持有容量，避免把所有缺货错误都判为泄漏。

适用场景与价值：编辑判断：训练集群扩容失败时，助手可按同一证据链汇总日志、指标与容量归属，减少在控制台间反复查找。技能明确只运行只读诊断，把修复方案交给用户；区别于近期通用编码技能及 Expo 平台知识。

限制与后续观察：要求相应日志、监控和资源查看权限，适用于 Standard 集群；Autopilot 不能关闭自动修复。恢复异常节点不会自动给新池腾出容量，整片 TPU 修复还会重建节点池。尚缺独立效果数据，应看公开故障复跑、误诊率及跨项目归属检查的完整性。

10 · Trusted Agent Delegation：代理身份之外，还要表达用户关系

事件简介：Cloudflare 宣布 Trusted Agent Delegation 联盟，讨论云端个人代理代用户访问网站时的身份、信誉与责任。与昨日访问分析和放行策略不同，本次增量是跨机构协议协调倡议，尚不是已完成互通的新授权协议。

技术机制：文章区分代理运营者身份、会话、账户和更强用户标识：Web Bot Auth 以请求签名识别代理平台，OAuth 可传递账户关系，MOLE 探索无需用户专属标识的信誉与限流。网站还需要机器可读方式表达允许哪些动作，单靠 robots.txt 的抓取路径规则不够。

实际影响：编辑判断：共享代理替多人购物时，只封代理会连带阻断正常用户；若能传递必要的用户关系和可核对声明，网站才有条件对具体账户作决策。不同场景需要的信息强度应分别确定。

限制与后续观察：多层代理链如何表达、声明如何验证仍待完善，本地代理也非初始重点。联盟计划通过会议与 IETF 协作细化问题；应跟踪公开规范、多个独立实现的互通、撤销与隐私测试，不能把倡议写成已解决交易授权和责任归属。
