01 · EMR 8.2：数据湖的并发写入与增量刷新进入长期支持版

事件简介：AWS 发布长期支持版 Amazon EMR 8.2，升级 Spark 4.1.3、Iceberg 1.11.0 与 Delta Lake 4.2.0。这些组件分别负责分布式计算和数据湖表管理；本次改变覆盖 EC2、EKS 与 Serverless 三种运行方式。

技术机制：多个集群可借 S3 条件写入并发更新同一 Delta 表，无需 DynamoDB 日志存储。Iceberg 物化视图把查询结果预先保存，刷新时只处理变化，覆盖投影、内连接、过滤及 SUM、COUNT 聚合；最终用户身份还能传到 Lake Formation 与 S3。

实际影响：编辑判断：分阶段汇总订单的数据团队，可把中间结果声明为 SQL 物化视图，减少每轮重算整张来源表；多集群写入则少维护一套日志存储组件。仍须用自己的增量与并发任务验收。

限制与来源：不同部署方式新增能力不同，例如三种执行器伸缩配置仅列于 Serverless。最高 97% 的用户配置延迟降幅是 EC2 特定场景的厂商数据，不是整个作业提速承诺；公告未给 LTS 的具体维护期限。

03 · Grafana Cloud Logs 全文搜索：先定位可能含目标字符串的数据

事件简介：Grafana Cloud Logs 宣布全文搜索正式可用，在 Loki 原有标签索引之外加入 Logline 二级索引。它解决只知道交易编号、却不知道服务或日期时，需要扫描大量压缩日志的问题；本次是日志检索更新。

技术机制：新索引告诉 Loki 哪些数据可能包含目标字面字符串，让查询跳过其他数据。现有 LogQL 的 |= 精确字符串、部分 |~ 正则，以及结构化元数据和 JSON 解析后的字面过滤可走加速路径，无需把每个用户编号都做成标签。

实际影响：编辑判断：客服交来一个两周前的交易号时，值班者可保留较宽时间范围查询，减少反复猜服务与时间、或另建全文系统的操作。避免高基数标签，也就是大量不同标签值造成的流数量膨胀。

限制与来源：部分高级正则不支持；这次公告针对托管 Cloud Logs，不能直接推定自托管 Loki 已具备相同能力。约一成计算和存储开销及客户提速案例均由厂商给出，非本期复测；公告称当前不额外收费。

04 · AHP 工程披露：跨设备会话以服务器状态和动作回放对齐

事件简介：GitHub 披露 Agent Host Protocol（AHP，代理宿主协议）的跨设备实现，展示 VS Code 与 GitHub 两套独立宿主怎样共用会话。本次新增证据是协议状态设计及互通经验，延伸本周 Qwen Code 的单产品重连主题。

技术机制：协议按 URI 标识通道，根、会话与聊天通道必选，终端等可扩展。服务器裁定状态，客户端发送动作，归约函数依序计算新状态；断网期间的动作在重连后提交，等服务器确认再确定结果，避免各端自行认定成功。

实际影响：编辑判断：团队做移动审批入口时，可让手机与编辑器读取同一会话，而不是另存聊天副本；协议库覆盖多种语言，减少每种客户端各写一套状态接线。宿主独立于编辑器窗口，也使关闭窗口不必结束任务。

限制与来源：TypeScript 与 Rust 宿主互通曾暴露终端输出表达不足、客户端猜测 URI 结构等问题。协议保留自定义方法与元数据，不能由采用名称推断所有扩展互通；Copilot 应用直连入口仍在 Experimental 设置中。
