04 · GitHub 九月可用性复盘：后台限流不能只盯副本延迟

事件简介：GitHub 发布九月可用性报告，解释两次事故及改进方向。其中一次后台清理任务把共享数据库主节点的连接耗尽，另一场则是代码审查服务已报成功、评审内容却未完整交付；这些是历史事故的近期复盘。

技术机制：清理任务按副本落后程度放慢写入，却没有同时检查主节点负载；缺少快速超时的请求持续等待，令牌创建重试又继续加压。审查事故中，上游只为部分客户返回含评论的完整结果，消费方未把缺失结果识别为失败。

实际影响：编辑判断：数据库维护应同时观察主库容量与副本状态，并在超时和重试上设恢复边界；异步任务验收则应检查结果是否真正送达，避免仅靠“作业成功”状态掩盖业务失败。

限制与来源：暂停清理、降低负载和回滚分别用于缓解事故；更完善的保护及监控仍是后续工作。报告的容量、死锁下降等数字来自 GitHub 自身，不构成任意数据库或审查系统的通用收益。
