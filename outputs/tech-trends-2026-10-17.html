01 · gopls 交互式重构：先问清参数，再修改代码

事件简介：Go 团队介绍 gopls 的交互式重构，并提出语言服务器协议（LSP）的扩展，让编辑器在生成代码修改前收集多步输入。gopls v0.24.0 与 VS Code Go 扩展 v0.56.0 已提供支持；文章介绍现有能力，并非宣布全部规划功能同时上线。

技术机制：以结构体标签为例，工具先询问 json、yaml、db 等标签键，再询问 snake_case 等命名规则，最后生成修改；实现接口时则动态搜索接口，并收集泛型类型参数。语言服务器负责语言语义，编辑器负责呈现交互，减少为每种编辑器单独实现同一重构逻辑的需要。

实际影响：编辑判断：给数据库对象同时补 JSON 与数据库字段映射时，开发者可一次选定规则，少做逐字段改名和清理；生成接口方法后仍需编写实际方法体。

限制与来源：跨文件、跨包移动声明仍为预览，修改函数签名等仍在路线图；Neovim、Emacs 的接入只是概念验证。协议扩展尚属提案，不能推断所有 LSP 客户端已经兼容。
